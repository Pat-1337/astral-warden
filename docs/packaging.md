# Packaging

## Scoop (Windows)

Each release attaches `gpu-warden.json`, a Scoop manifest generated from `packaging/scoop/gpu-warden.json` with the version and portable zip hash filled in. Scoop installs the portable build and persists `gpu-warden.toml` and `gpu-warden.log` across updates.

```
scoop install https://github.com/Pat-1337/gpu-warden/releases/latest/download/gpu-warden.json
```

`scoop update gpu-warden` re-reads that URL, so it always moves to the latest release. You don't need a bucket repo.

**Start at logon** in a Scoop install points the logon task at `scoop\apps\gpu-warden\current\gpu-warden.exe`, so the task follows Scoop updates instead of copying the binary to Program Files.

## AUR (Arch Linux)

`packaging/aur/` holds `PKGBUILD` and `gpu-warden.install` for **gpu-warden-bin**, which repackages the release's Linux systemd tarball:

| File | Installed to |
|---|---|
| binary | `/usr/bin/gpu-warden` |
| unit | `/usr/lib/systemd/system/gpu-warden.service` |
| `i2c-dev` | `/usr/lib/modules-load.d/gpu-warden.conf` |
| udev rule (keeps ModemManager off the WireView Pro II) | `/usr/lib/udev/rules.d/70-gpu-warden.rules` |
| config | `/etc/gpu-warden/config.toml` (`backup`, so pacman keeps your edits; generated by `gpu-warden config`) |

Users then run:

```
sudo systemctl enable --now gpu-warden
```

### One-time setup to publish

1. Create an account at https://aur.archlinux.org and add an SSH public key to it.
2. In the GitHub repo settings, add two Actions secrets:
   - `AUR_SSH_PRIVATE_KEY`: the matching private key
   - `AUR_EMAIL`: the email for AUR commits
3. Push a release tag.

The `aur` job in `release.yml` then sets `pkgver`, runs `updpkgsums`, generates `.SRCINFO`, and pushes to `ssh://aur@aur.archlinux.org/gpu-warden-bin.git`. The AUR creates the package on the first push. Without the secrets, the job is skipped.

### Testing locally

The package was test-built in an `archlinux` container (x86_64 under emulation; pacman needs `DisableSandbox` there):

```
updpkgsums && makepkg -f && namcap PKGBUILD *.pkg.tar.zst
```

## Nix

`flake.nix` builds from source for `x86_64-linux` and `aarch64-linux`, with `Cargo.lock` pinning the crates and `flake.lock` pinning nixpkgs. `packaging/nix/` holds the package and the NixOS module.

| Output | What |
|---|---|
| `packages.<system>.default` | `bin/gpu-warden`, `lib/libgpu_warden.so`, `include/gpu_warden.h`, the udev rule, and the `i2c-dev` modules-load file |
| `overlays.default` | adds `pkgs.gpu-warden` |
| `nixosModules.default` | `services.gpu-warden` |
| `checks.<system>` | builds the package and evaluates the module |

Try it without installing:

```
nix run github:Pat-1337/gpu-warden -- status
```

On NixOS, add the flake as an input and import the module:

```nix
{
  inputs.gpu-warden.url = "github:Pat-1337/gpu-warden";

  outputs = { nixpkgs, gpu-warden, ... }: {
    nixosConfigurations.pc = nixpkgs.lib.nixosSystem {
      modules = [
        gpu-warden.nixosModules.default
        {
          services.gpu-warden = {
            enable = true;
            settings.power_cap.percent = 70;
          };
        }
      ];
    };
  };
}
```

The module:

| Sets | Value |
|---|---|
| `boot.kernelModules` | `i2c-dev` |
| `services.udev.packages` | the package, for the rule that keeps ModemManager off the WireView Pro II |
| `/etc/gpu-warden/config.toml` | generated from `settings`; unset keys keep their defaults (`gpu-warden config` prints them) |
| `systemd.services.gpu-warden` | runs as root at boot, restarts on failure and when `settings` change |

The wrapper puts `notify-send`, `runuser`, and `wall` on `PATH` and adds `/run/opengl-driver/lib` to `LD_LIBRARY_PATH`, where NixOS keeps `libnvidia-ml.so` for the power cap. The Nix build doesn't update itself, and `gpu-warden install` isn't used; `nix flake update` and a rebuild move to a new version.
