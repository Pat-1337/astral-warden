# Packaging

## Scoop (Windows)

Each release attaches `astral-warden.json`, a Scoop manifest generated from `packaging/scoop/astral-warden.json` with the version and zip hash filled in.

```
scoop install https://github.com/Pat-1337/astral-warden/releases/latest/download/astral-warden.json
```

`scoop update astral-warden` re-reads that URL, so it always moves to the latest release. You don't need a bucket repo.

**Start at logon** in a Scoop install points the logon task at `scoop\apps\astral-warden\current\astral-warden.exe`, so the task follows Scoop updates instead of copying the binary to Program Files.

## AUR (Arch Linux)

`packaging/aur/` holds `PKGBUILD` and `astral-warden.install` for **astral-warden-bin**, which repackages the release's Linux systemd tarball:

| File | Installed to |
|---|---|
| binary | `/usr/bin/astral-warden` |
| unit | `/usr/lib/systemd/system/astral-warden.service` |
| `i2c-dev` | `/usr/lib/modules-load.d/astral-warden.conf` |
| config | `/etc/astral-warden/config.toml` (`backup`, so pacman keeps your edits; generated by `astral-warden config`) |

Users then run:

```
sudo systemctl enable --now astral-warden
```

### One-time setup to publish

1. Create an account at https://aur.archlinux.org and add an SSH public key to it.
2. In the GitHub repo settings, add two Actions secrets:
   - `AUR_SSH_PRIVATE_KEY`: the matching private key
   - `AUR_EMAIL`: the email for AUR commits
3. Push a release tag.

The `aur` job in `release.yml` then sets `pkgver`, runs `updpkgsums`, generates `.SRCINFO`, and pushes to `ssh://aur@aur.archlinux.org/astral-warden-bin.git`. The AUR creates the package on the first push. Without the secrets, the job is skipped.

### Testing locally

The package was test-built in an `archlinux` container (x86_64 under emulation; pacman needs `DisableSandbox` there):

```
updpkgsums && makepkg -f && namcap PKGBUILD *.pkg.tar.zst
```
